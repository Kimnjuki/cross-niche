### 1.2 Backend (Convex)
- **Deployment**: `canny-mule-83.convex.cloud` (prod), local `convex dev`
- **Schema**: 60+ tables covering content, users, gaming tools, threat intel, community, SEO, monetization
- **Auth**: Clerk JWT validation via `authIdentities` table binding
- **Key Tables for Security Tools**:
  - `gamingSecurityScores` — stores checkup results (sessionId, userId, answers, score, band, expiresAt)
  - `consents` — consent records for data processing
  - `securityEntities` — platform/game/publisher/tool entities for grades
  - `officialLinks` — human-verified official support/recovery URLs
  - `recoveryPlaybooks` — versioned, reviewed recovery guides
  - `communityThreatReports` — user submissions (pending/verified/dismissed)

## 3. Data Flow & Trust Boundaries

### 3.1 User Data Flows
```
Browser (Anonymous)
  ├─ SteamScanner → sessionStorage only (no network)
  ├─ GamingSecurityCheckup → sessionStorage + optional Convex (saveSecurityScore)
  ├─ ScamChecker → ?
  ├─ Analytics (GA4) → Google
  ├─ Ads (AdSense/Adsterra) → Google/Adsterra
  └─ Clerk Auth → Clerk (if signed in)

Convex Backend
  ├─ gamingSecurityScores (30-day TTL, sessionId + optional userId)
  ├─ consents (consentId linked to scores)
  ├─ communityThreatReports (userId optional, displayName)
  └─ users (Clerk-synced, PII: email, username, displayName)
```

### 3.2 Trust Boundaries
| Boundary | Current State | Gaps |
|----------|---------------|------|
| Anonymous browser ↔ Convex | GamingSecurityCheckup sends scores with sessionId | No rate limiting on `saveSecurityScore`; consent checked but not enforced for anonymous |
| Browser ↔ Clerk | AuthProvider wraps app | Clerk keys in browser bundle (public key only) |
| Convex ↔ External | None observed in schema | No evidence of external API calls from mutations |
| Admin ↔ Content | ContentEditor component | No separate admin surface observed |

### 3.3 Secrets Inventory (Names Only)
| Secret | Location | Purpose |
|--------|----------|---------|
| `VITE_CONVEX_URL` | `.env`, `.env.local`, `.env.example` | Convex deployment URL |
| `CLERK_PUBLISHABLE_KEY` | `.env` files | Clerk frontend auth |
| `CONVEX_DEPLOY_KEY` | CI/CD (not in repo) | Convex deployment |
| `SENTRY_DSN` | `.env` files | Error tracking |
| `GA_MEASUREMENT_ID` | `.env` files | Google Analytics |
| AdSense/Adsterra keys | `.env` files | Monetization |
